## §1 判据：一个 grep 定在线/离线

```bash
grep -c 'sparseunet32_636.pth to GPU' exp/<ds>/<run>/train.log    # 1=在线 0=离线
grep -c 'use_lovasz = True'          exp/<ds>/<run>/config.py     # 0=名字喊 lovasz 但没开
```

第一个可靠是因为 `train.py:373` 是唯一分叉点：离线时 `VLM_3D = None`，日志里不可能出现 `network_template.py`。
`num_worker` 从 2 到 24 有 9 种取值，所以**每迭代耗时不能单独用来判断**。

## §3 变量三层归类

| 层 | 变量 | 处置 |
|---|---|---|
| **层 1（5 个）** | `ps_thresh` 0.6 / `epoch` 20 / `batch_size` 12 / 评估（crop=None + 2cm） / `num_worker` 2–24 | 忽略。num_worker 只影响速度，以后统一 ≥16 |
| **层 2（3 个）** | `ai_thresh`（Sc++ **0.95** / Sc200 **0.90**）、head lr（**0.007** / **0.001**）、折数（regis1） | 官方预设，**只需同格内一致** |
| **层 3（4 个，硬约束）** | 伪标签模式 / 训练点数 / 随机种子 / 损失函数 | 见下 |

**层 3 的具体规定**

| 变量 | 规定 | 当前违规 |
|---|---|---|
| 伪标签模式 | 同格内不混比 | Sc200 1-shot：base 在线、sym/M5 离线 |
| 训练点数 | Sc++ 全 102400；Sc200 1-shot 65536、5-shot 102400 | Sc200 混用（65536×103 / 102400×14） |
| 随机种子 | 只认 s42 / s7 / s13 | 7 个随机 seed 的实验（Sc++ 4 + Sc200 3） |
| 损失函数 | 主表纯交叉熵 | Sc++ 4 个假 Lovász 已作废；Sc200 26 个真 Lovász 移出主表 |

**影响量级**：seed（**3–4 分**，Sc++ 1-shot 实测）> 伪标签模式（1.4–2.9）> 折数（1–2）> 点数（0.35）> num_worker（0）。

## §4 作废（结果不可用）

| 实验 | 数值 | 原因 |
|---|---|---|
| `scpp_base_lovasz` / `scpp_base_lovasz_k5` / `scpp_sym_lovasz` / `scpp_sym_lovasz_k5` | 0.2804 / 0.3150 / 0.2986 / 0.3103 | **没开 `use_lovasz=True`**，是纯 CE + 随机 seed（20363522 / 20269292 / 31853493 / 25559278） |
| `sc200_k1_offline` | 0.4038 | config 写 5 折，实际最终值是 **regis2** 的 |
| `support_ontr_s42_BUG_vlm` / `support_xl_s42_BUG_vlm` | — | VLM 加载 bug |
| `support_base_s42` / `support_rep3_s42` / `support_sym_s42` / `support_ontr_linear_s42` / `support_xl_linear_s42` | 0.10–0.15 | PL 只在 support 场景读取，100% 假阳性 |
| `sc200_k1_XLu_s7` | — | 训练崩溃 |
| `m5_elr_s7`（两库） | loss 变负 | `log(1-dot)` 冲向 −9 |

**连带作废的结论**：
1. 「Sc++ 加洛瓦兹掉 3.00」——那 3.00 是 seed 25559278 vs 42 的差
2. 「Sc++ 早期 Lovász −0.47」——同因
3. 「Sc++ 从未跑过洛瓦兹 + 102400 + 跨层」——Sc++ **全部 102 个实验都是 102400**，且从未开过 Lovász
