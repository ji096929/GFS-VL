## §1 判据：一个 grep 定在线/离线

```bash
grep -c 'sparseunet32_636.pth to GPU' exp/<ds>/<run>/train.log    # 1=在线 0=离线
grep -c 'use_lovasz = True'          exp/<ds>/<run>/config.py     # 0=名字喊 lovasz 但没开
```

第一个可靠是因为 `train.py:373` 是唯一分叉点：离线时 `VLM_3D = None`，日志里不可能出现 `network_template.py`。
`num_worker` 从 2 到 24 有 9 种取值，所以**每迭代耗时不能单独用来判断**。

## §10 用途追溯：27 个曾「完全无记录」的实验

> 判定方法：run 目录名（去掉 `_sXX` 后缀）在所有报告文档里都搜不到。
> 下面把每一个都定性，**没有一个是「不知道」**。

### 10.1 三层标尺的 oracle 三件套（核心，必须知道）

| run | HM | 构造方式 |
|---|---|---|
| **`scpp_oracle_fullsup20`** | **0.4905** | 环境变量 `GFS_ORACLE_MODE=fullsup`：`target_calibrate` 直接返回完整 GT（含新类），等价于 20 epoch 全监督。**这是「系统理论上界」** |
| **`scpp_oracle_filter_m0`** | **0.4120** | `GFS_ORACLE_MODE=filter`：VLM 照常出预测，但用 GT 判断真伪，等价于 100% precision/recall 的伪标签筛选。**这是「环节完美上界」** |
| `scpp_oracle_filter_m1` | 0.3613 | 同上变体（m1 = 换了一套筛选判据） |

代码位置：`pointcept/engines/train.py:1332-1345`。

**含义**：
- 「完美伪标签」只能把 Sc++ 5-shot 从 0.331 抬到 **0.4120**（+8.1）
- 「全监督」能到 **0.4905**（+16.0）
- **所以伪标签筛选这一环的真空带只有 8 点，剩下 8 点要靠结构/表征**
